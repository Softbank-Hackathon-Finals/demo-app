# WebSocket 유휴 수신 중단과 재접속 검증

닫힘 통지를 받은 연결의 재접속 외에, 열린 것처럼 보이지만 수신이 멈춘 연결을
구분하도록 보강했다. 실제 서버 장애·클라우드 컷오버가 아닌 격리 앱/브라우저 시험이다.

## 재현과 구현

기존 코드에 새 협상 조건을 시험하는 수신 중단을 주입했을 때 화면은 18초 뒤에도
온라인이었다. 새 서버는 정확한 5초 주기 capability를 hello에 넣고 기존 status 프레임을
유휴 상태에서도 보낸다. UI는 해당 capability를 받은 연결에서만 유효 수신 후 15초
타이머를 관리하고, 수신이 없으면 오프라인 표시·마지막 ID 이후 재접속을 수행한다.

새 프레임 종류·업무 쓰기·추가 DB 쿼리는 없다. 기존 1012 종료와 전송 잠금을 유지한다.
구형 서버가 capability를 생략하면 기존 동작을 유지한다. 잘못된 주기값은 쓰기나
온라인 상태를 허용하는 근거로 사용하지 않는다.

## 검증

| 환경 | 결과 |
| --- | --- |
| Python 전체 + 실제 격리 PostgreSQL 17.11 | 152 통과 |
| Chromium 전체 / 메모리 시험 저장소 | 16 통과 |
| WebKit 전체 / 메모리 시험 저장소 | 16 통과 |
| 두 브라우저 전체 / 실제 PostgreSQL Store | 32 실행 통과 |
| Node 전송·멱등 키·cursor 단위 | 10 통과 |
| Ruff·JS 문법·기존 QR 자산 검사 | 통과 |

정상 유휴 연결의 유지, 수신만 끊은 연결의 오프라인 표시·재접속, 구형 서버의
capability 생략, 잘못된 문자열/boolean/0/미지원 주기 거부를 확인했다.
기존 메시지 쓰기·멱등 재시도·같은 주소 시험 전환·첨부 재시도도 전체에 포함한다.
새 backend 시험은 읽기 전용 저장소 대역으로 heartbeat에 쓰기가 없음을 확인한다.

실제 PG 실행은 기존 `testing/browser_database.py`와 고정 pnpm으로 수행했다.
새 Unix socket DB와 비관리자 앱 역할만 사용하고 클라우드 자격은 배제했다.
첨부 저장소는 시험 대역이며 DB 이전·TLS·실제 S3 동등성을 시험한 것은 아니다.
실행 종료 후 자신이 만든 PostgreSQL을 정상 종료·정리했다.

최초 PG 실행은 151 통과·1 실패였다. 새 hello 필드와 맞지 않던 기존 **엄격한**
예상 응답에 해당 필드를 추가했고 다른 필드 검사는 유지했다. 새 DB에서 전체를
다시 검증했다. 기존 실패와 정리 결과는 별도로 보존했다.

## 운영 미검증 범위

운영 이미지·서버는 갱신하지 않았다. 기존 실제 두 앱은 이전 배포본이다.
새 서버/자산의 같은 이미지 배포, 실제 고정 주소와 프록시를 통한 재접속,
휴대폰 실기기 및 실제 컷오버 중 데이터 보존은 별도 인수다.
15초는 foreground JS 타이머 기준이며 절전·백그라운드에서도 같은 상한을
보장하지 않는다. 연결 표시만으로 DB 쓰기 성공이나 무중단을 주장하지 않는다.

[summary.json](summary.json)에 검사 범위와 원본 지문을,
[source-manifest.json](source-manifest.json)에 실행한 구현·시험 소스를 고정했다.
첫 재현의 텍스트 로그는 보존했다. 기본 출력 폴더의 최초 브라우저 trace는 후속
실행에서 교체돼 보존됐다고 주장하지 않으며, 후속 엔진별 결과는 별도 경로에 보존했다.
