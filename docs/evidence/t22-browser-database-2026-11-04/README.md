## 최초 실패와 수정

최초 실제 DB 시험은 17/18이었다. WebKit에서 시험 중계 `route.fetch()`가 첫 첨부를
0바이트로 전달했고 재시도는 원래 내용을 보내 DB가 충돌을 거부했다. 서버의 정상적인
보호 동작이며 이를 완화하지 않았다. 메모리 FakeStore는 첨부 메타데이터 충돌을 검사하지
않아 기존 시험에서 드러나지 않았다.

브라우저의 multipart를 그대로 소비하고 앱 저장이 끝난 뒤 시험 호스트에서 성공 응답만
503으로 바꾸도록 수정했다. 이는 TCP 연결 단절 자체의 시험이 아니라 저장 성공 응답의
유실을 클라이언트 재시도로 복구하는 시험이다. 처음 실패한 로그·trace는 비공개로 보존했다.
일반 sandbox에서 HTTP 소켓 시험 3개가 권한 거부된 실행도 보존했으며, 최종 전체 실행은
소켓 사용이 허용된 환경에서 수행했다. Starlette 테스트 클라이언트 deprecation 경고 1건이 있다.

## 경계

두 환경은 같은 테스트 호스트의 앱 인스턴스이며 하나의 실제 DB를 공유한다. 첨부 바이트는
시험 대역이다. 같은 프로세스의 로컬 라우트 전환으로 실제 Cloudflare·EKS·RKE2 전환이나
DB 복제·fencing·데이터 이전을 검증했다고 주장하지 않는다. 실제 저장소 조건부 쓰기는
[별도 SeaweedFS 시험](../t22-immutable-attachments-2026-11-04/README.md)과 구분한다.

새 도구는 기존 DB 접속 정보를 받지 않고 새 PostgreSQL만 만든다. 테스트 호스트의 reset
기능도 개인 소유·비공개 임시 디렉터리의 지정 형식 DB만 허용한다. 원격 접속 설정이나
일반 DB 이름·공개 권한·심볼릭 링크는 거부한다. 테스트 라우트는 서비스 이미지에 없다.

실제 휴대폰에서 안정 URL을 이용한 AWS→온프렘 채팅 지속은 T22 통합 인수로 남는다.
