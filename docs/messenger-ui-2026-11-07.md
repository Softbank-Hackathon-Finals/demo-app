# T22 메신저 UI와 대화 내 모의 송금

2026-11-07 KST. 기능 브랜치 `feature/T22-kakao-chat`, 관련 작업 platform#15.
기존 `feature/T22-service-webapp`의 로컬 송금·원장 구현을 재사용해 채팅 중심으로 재구성했다.
원격 main 기준은 `3a1a9135a2d133e794109525554d9d373b49f84a`다.

## 사용자 동작

- 데스크톱은 메뉴·대화 목록·대화방을 함께 표시하고, 휴대폰은 대화방과 목록 사이를 이동한다.
- 하나의 실제 공개 대화방을 사용한다. 참여자 목록은 실제 메시지/지갑 기록에서 관측한 별명이며 접속자 수나 인증 신원이 아니다. 존재하지 않는 대화·메시지를 앱에 미리 넣지 않는다.
- 메시지·첨부·이모지를 보내며 현재 표시한 최근 대화에서 검색한다. 목록 미리보기도 실제 수신한 기록을 사용한다.
- 입력창의 송금하기는 모의 포인트 지갑이 없으면 먼저 생성을 안내하고 같은 송금 흐름으로 돌아간다.
- 받는 사람 → 금액 키패드 → 확인 → 저장 확인 순으로 송금한다. 대화에는 금액·받는 사람·메모를 안전한 DOM 텍스트로 표시한다.
- 응답을 잃거나 쓰기가 보류되면 원래 본문과 멱등 키를 유지한다. 대화 아래에서 미확인 포인트 요청을 다시 열어 같은 요청으로 재시도할 수 있다.
- 전환 관찰은 별도 패널로 유지한다. 앱의 환경 표시는 서버 설정과 이 브라우저의 관측이며 클라우드 신원이나 전체 이전 성공의 증거가 아니다.

## 기존 플랫폼 계약

DB schema·HTTP/WebSocket API·S3 SDK·Secrets Manager 직접 조회를 변경하지 않았다.
모의 지갑과 송금은 기존 메시지 본문의 `BRAVO-LEDGER/1` 이벤트다. 서버는 금융 원장의 잔액·
소유권을 집행하지 않으므로 실제 은행·결제 서비스로 설명하지 않는다. 카카오톡 API에 연결하지 않는다.

잔액 전체 합계만으로 이전 중 거래 유실을 검증할 수 없다. T13의 원본 대조, T18의 요청별 DB 대조와
T19의 실제 증거·판정은 기존 플랫폼에서 수행해야 한다. `/stage.html`도 읽기 전용 모의 원장 표시다.

## 수신·응답 순서에서 발견한 수정

원장 replay의 중복 제거와 채팅 DOM의 중복 제거를 독립적으로 유지한다. POST 응답이 먼저 도착해
원장에 기록됐더라도 나중의 WebSocket 기록은 대화 카드에 전달한다. 반대로 WebSocket이 먼저
도착하고 POST 응답을 잃으면 원장에 이미 확인한 거래의 금액을 미확인 요청으로 다시 차감 표시하지 않는다.
확인한 POST 기록은 카드로 즉시 표시하되 스트림 재접속 커서는 앞당기지 않는다.

회귀 시험은 실제 저장과 스트림 전달 이후 POST 응답을 보류한다. 이 구간에서 잔액은 한 번만 차감되고
카드 한 개가 표시되며, 원래 키의 재시도가 완료돼도 저장 행과 카드는 한 개인지 확인한다.
받는 쪽 잔액 갱신과 키패드 단계의 키보드 포커스도 보완했다.

## 검증 범위

- Node 단위 시험 23 PASS, 스크립트 문법 검사와 QR 고정 자산 대조.
- Python 152 PASS / 4 SKIP. 실제 PostgreSQL 설정 또는 OpenSSL이 필요한 시험은 로컬 설정 부재로 건너뛰었다.
- Chromium·WebKit 40 PASS / 3.1분: 메시지·첨부·QR·모바일 이동·검색·이모지·송금·응답 유실·쓰기 보류·재접속을 검증했다.
- 목록 화면에서 지갑을 여는 모바일 경로도 두 브라우저에서 추가 확인했다(2 PASS). 지갑 dialog는 숨겨지는 대화 패널 밖에 배치한다.
- 로컬 테스트 호스트는 명시적인 메모리 저장소/첨부 대역과 실제 HTTP/WebSocket을 사용한다. 실제 AWS/RKE2 이전이나 운영 금융 인증을 완료한 결과는 아니다.
- 320·360·390·768·1440px에서 가로 넘침이 없음을 확인하고 데스크톱·휴대폰·목록·송금 화면을 시각 확인했다. 화면 검토 데이터는 로컬 시험 호스트에만 생성했다.

Windows 전체 시험 중 기존 POSIX 전용 DB reset fixture가 `os.getuid` 부재로 실패했다.
파일 소유권·모드 검사가 없는 환경에서는 설정을 읽거나 연결하지 않고 명시적으로 거부하도록
별도 수정했다. Unix socket PostgreSQL 시험을 Windows에서 허용하거나 소유권 검사를 생략하지 않는다.

필수 검사 형식은 기존 CI를 유지한다. 데모 앱과 공유 플랫폼의 운영 배포는 이 UI 작업에서 수행하지 않는다.

첫 원격 CI `42280506655`는 Python 정적 검사·153 PASS/3 SKIP 및 Node 단위 검사 후,
Linux WebKit의 종료 코드 1012 표시를 고정한 두 브라우저 단언에서 실패했다(38 PASS/2 FAIL).
서버가 보내는 코드와 브라우저가 관측한 코드를 동일하다고 추정하지 않도록 관측 코드를 항상 기록한다.
시험은 UI와 독립적으로 native CloseEvent를 수집해 표시 값과 대조한다. 서버의 실제 1012 발행 검증은
기존 ASGI 시험에서 그대로 유지하고 재접속·원장 대조·중복 방지 단언도 유지한다.
수정 후 해당 채팅·발표 화면의 native 관측 대조를 Chromium·WebKit에서 다시 확인했다(4 PASS).
