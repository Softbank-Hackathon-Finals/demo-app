# T22 메시지 pipeline 추가 검증

T18의3r 제안을 적용하고 실패·취소·풀 복구 시험을 보강한 후보를 별도로 검증했다. 운영 시퀀스/락 순서는 유지한다.

- PG17 비관리자 역할42시험 통과: INSERT 이후 오류 롤백, 실제 잠금 대기 후 취소, 풀 복구와 커밋 후 응답.
- PG18.4 직접/PgBouncer 각29불변식 통과. 논리 디코딩600행의커밋·ID순서, 동시 멱등성, 응답 유실 후120개쓰기 각각1행, 잠금/세션 설정 복구. 직접 경로 앱 회귀31개 통과.
- 로컬 PG16·PgBouncer·Nginx에서 쓰기50/s·읽기150/s, 대상50%, 각30초. baseline20/40ms는 오류·지연 실패. 후보는 두 칸 모두 HTTP 실패·유실·중복0이나 **20ms의 p95 창1개가 기준 초과**,40ms는3창 통과다.

`result.json`은 해당 실패까지 포함한 공개 요약이다. 모의RTT이며 첫시험은 이미지 누락으로 실행 전 종료, 의존 이미지 준비 후 별도 출력 폴더에서 실행했다. 후보와 baseline의 관측/의존성 구성이 완전히 동일하지 않으므로 순수한 성능 개선 배율을 주장하지 않는다. Nginx IPv6 연결 재시도도 관측했지만 지연 실패의 원인으로 단정하지 않는다.

실제 클라우드·Tailscale·TLS·장시간 부하 및 PAUSE 중단 예산은 미검증이다. 불변식 통과와 운영 성능 자격을 구분하며 이 PR만으로 T22 완료나 컷오버 준비를 선언하지 않는다.

## 반복과 Edge 대조 시험

동일 후보의20/40ms 각각2회 반복을 추가했다. 기본Edge에서20ms는두회차모든창PASS,40ms는두회차모든창FAIL(p95약15초)이었다. 확인한쓰기의유실·중복은0이었다.

제품앱·기준·DB경로는유지하고,임시시험Edge의업스트림만실제DockerIPv4게이트웨이로고정했다. 두20ms와첫40ms는모든창PASS,두번째40ms는첫창P95FAIL이었다(전체쓰기p95637ms,읽기678ms). IPv6연결거부는사라졌으나성능자격은통과하지않았다. 기본Edge의15초증상에영향을주는경로로의심할근거이며,유일한원인이나모든장애해결로단정하지않는다.

`repeat-summary.json`에총8개칸의원래창판정과실패를모두남겼다. 보고용집계기에서UNKNOWN을제거하지않았다. 실제클라우드벤치마크가아니며,별도장시간실패기록을대체하지않는다.
